# Деплой на отдельный сервер

Инструкция для установки на чистый Linux-сервер (Ubuntu/Debian — команды
ниже под них; на другом дистрибутиве отличается только установка Docker).
Доступ — по IP, без домена и HTTPS (фронтенд сам определяет адрес API по
адресу страницы, см. README).

Postgres (`5432`) и Adminer (`8080`) в `docker-compose.yml` слушают на всех
интерфейсах (`0.0.0.0`) — сознательно оставлено как есть для этого
сценария. Это означает, что при отсутствии внешнего firewall они доступны
из интернета всем, кто знает IP сервера и пароль из `.env`. Минимум —
поставьте пароль `POSTGRES_PASSWORD` не короче, чем для `admin`-аккаунта
приложения. Если сервер позже окажется в открытом интернете без VPN —
стоит вернуться и закрыть эти два порта (`ufw deny 5432/tcp`,
`ufw deny 8080/tcp`, либо убрать `ports:` у `postgres`/`adminer` в
`docker-compose.yml` и ходить в БД через `docker compose exec`/SSH-туннель).

## 1. Подготовка сервера

```bash
# Docker Engine + Compose plugin
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER
# перелогиньтесь (или newgrp docker), чтобы группа применилась

# Git, если будете клонировать репозиторий
sudo apt-get update && sudo apt-get install -y git
```

Проверка: `docker compose version` должна вывести версию, а не ошибку.

## 2. Открыть порты в firewall сервера

Приложению нужны снаружи:
- `5173/tcp` — веб-интерфейс
- `3000/tcp` — API (фронтенд ходит в него из браузера пользователя)
- `22/tcp` — SSH для управления сервером (и для встроенного в приложение
  SSH-терминала роутеров — это отдельное соединение сервер→роутер, порта
  сервера не касается)

Порты `5432` (Postgres) и `8080` (Adminer) — по решению выше оставляем
открытыми; если на сервере есть `ufw`:

```bash
sudo ufw allow 22/tcp
sudo ufw allow 5173/tcp
sudo ufw allow 3000/tcp
sudo ufw enable
```

Отдельно: сервер должен иметь сетевой доступ **к самим роутерам MikroTik**
(порт REST API, обычно 443, и 22 для SSH-терминала) — это исходящие
соединения с сервера, встречных правил на сервере не требует, но убедитесь,
что между сервером и роутерами нет своего firewall/NAT, блокирующего это.

## 3. Получить код на сервер

```bash
git clone https://github.com/istinx/mtkfleetman.git
cd mtkfleetman
```

(Обновление в будущем — `git pull`, см. раздел «Обновление» ниже.)

## 4. Настроить .env

```bash
cp .env.example .env
```

Отредактируйте `.env`:
- `POSTGRES_PASSWORD` — задайте свой (не `mtk`/`change-me` из примера)
- `JWT_SECRET` — сгенерируйте: `openssl rand -hex 32`
- `MASTER_KEY` — сгенерируйте отдельным вызовом: `openssl rand -hex 32`.
  Сохраните этот ключ вне сервера (менеджер секретов/сейф) — без него
  сохранённые пароли роутеров не расшифровать при восстановлении из
  бэкапа на новом сервере.
- `BOOTSTRAP_ADMIN_USERNAME` / `BOOTSTRAP_ADMIN_PASSWORD` — логин/пароль
  первого admin-аккаунта, создаётся автоматически при первом старте.
  Либо оставьте пустыми и создайте пользователя через `seed`-скрипт
  (см. README, `docker compose exec api node dist/scripts/seed.js`).

## 5. Запуск

```bash
docker compose up --build -d
docker compose ps        # все сервисы должны быть healthy/running
docker compose logs -f api worker   # Ctrl+C для выхода из просмотра логов
```

Первый билд (`--build`) компилирует backend/frontend внутри контейнеров —
на слабом сервере может занять несколько минут, дальнейшие рестарты
(`docker compose up -d` без `--build`) быстрые.

## 6. Проверка

```bash
curl http://localhost:3000/auth/login -X POST -H "Content-Type: application/json" \
  -d '{"username":"<ваш BOOTSTRAP_ADMIN_USERNAME>","password":"<пароль>"}'
# -> {"token":"..."} значит API и БД подняты и работают
```

С другого компьютера в браузере: `http://<IP-сервера>:5173`. Добавьте
первый роутер через интерфейс (см. пункт «Документация» в ☰-меню
приложения — там шаги настройки самого MikroTik: `www-ssl`, отдельный
API-пользователь и т.д.).

## 7. Резервное копирование

Данные живут в docker-томе `pgdata` (метрики, роутеры, пользователи,
зашифрованные пароли роутеров). Бэкап:

```bash
docker compose exec -T postgres pg_dump -U <POSTGRES_USER> <POSTGRES_DB> \
  > backup-$(date +%F).sql
```

Восстановление на новом сервере требует **тот же `MASTER_KEY`**, что был
при создании бэкапа — иначе пароли роутеров в БД останутся
нерасшифровываемыми (сами роутеры придётся заново вводить логин/пароль).
Держите её рядом с бэкапами БД, но отдельно от места, где лежит сам `.env`
на сервере.

## 8. Обновление

```bash
cd mtkfleetman
git pull
docker compose up --build -d
```

Если в обновлении была миграция БД — в README у каждого раздела есть
подпункт «Применение к уже развёрнутой базе» с точной командой
`docker compose exec -T postgres psql ...`. Применяйте миграции по порядку
номеров, которых ещё не было. На **новом** сервере с нуля (том `pgdata`
только что создан) миграции не нужны — `schema.sql` уже включает все
изменения из папки `migrations/` на момент последнего коммита.
